# retro — 每周工程复盘

> 来源：gstack-main/retro/SKILL.md（精简移植）
> 核心：Ship + Health + Pattern 三维度

## 触发条件

```
用户说"每周复盘"、"我们发了什么"、"engineering retrospective"
→ 执行这个 skill
```

建议在周末或冲刺结束时主动提出。

---

## 3个维度

### 1. Ship（发了什么）

**统计：**
```
- Commit 数
- LOC 增 / 删
- PR 数
- 关闭的 Issue 数
```

**分类：**
- 按文件/模块分类（哪个模块改动最多？）
- 与上周对比（是加速了还是减速了？）

---

### 2. Health（健康度）

**测试：**
```
- 新增测试覆盖率变化
- 测试是否在恶化？（新增测试少但改动多）
```

**技术债务：**
```
- 解决了多少技术债务
- 新增了多少技术债务
- 标记的 TODO 有多少？
```

**Bug：**
```
- 逃逸到生产的 Bug 数
- 是新功能还是回归？
- 平均修复时间
```

---

### 3. Pattern（模式识别）

**反复出现的问题：**
```
- 同一类问题出现了几次？
- 有没有可以系统性避免的模式？
```

**可以避免的浪费：**
```
- 花了很长时间但本可以避免的情况
- 走了弯路 → 记录教训
- 依赖没对齐导致的延迟
```

**改进建议：**
```
- 下周可以做的一件事来改进流程
- 具体的、可操作的
```

---

## 输出格式

```
# [日期] Weekly Retro

## Ship
- Commits: N
- Lines: +N / -N
- PRs: N

## Health
- 测试覆盖率: X% (+/- Y%)
- 技术债务: 解决N / 新增N
- Bug逃逸: N个（描述）

## Patterns
- [Pattern 1]: 描述
- [Pattern 2]: 描述

## Next Week
- [具体可操作的改进]
```

## 自改进

把教训记录到 evolver：
```
evolver.record("复盘模式识别", "发现了X模式", 
  solution="建议Y", success=True)
```
