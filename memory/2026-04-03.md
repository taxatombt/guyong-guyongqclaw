### 关键架构差异
1. claw-code用Rust (async/await)，顾庸x用Python (同步)
2. claw-code工具在同进程，顾庸x工具可外部进程
3. claw-code有namespace沙箱，顾庸x用hook做危险命令检测
4. claw-code支持Session Fork，顾庸x通过checkpoint/recover实现
**ConversationRuntime 结构：**
- session: Session - 会话状态
- api_client: C - API客户端（流式SSE）
- tool_executor: T - 工具执行器
- permission_policy: PermissionPolicy - 权限策略
- system_prompt: Vec<String> - 系统提示词
- usage_tracker: UsageTracker - 用量追踪
- hook_runner: HookRunner - Hook运行器
- auto_compaction_input_tokens_threshold: u32 - 自动压缩阈值（默认100K）

**核心循环 run_turn：**
1. 记录turn开始
2. 推送用户消息到session
3. loop循环（最多max_iterations次）：
   - 构建ApiRequest（system_prompt + messages）
   - api_client.stream(request) 获取AssistantEvent流
   - 解析events构建assistant_message
   - 提取pending_tool_uses
   - 推送assistant_message到session
   - 如果没有tool_use，break
   - 对每个tool_use：
     - 运行pre_tool_use_hook
     - 检查permission_outcome（Allow/Deny）
     - 如果Allow：tool_executor.execute
     - 运行post_tool_use_hook
     - 构建tool_result并推送到session
4. 可能触发auto_compact
5. 返回TurnSummary

**关键设计：**
- 流式处理：TextDelta, ToolUse, Usage, PromptCache, MessageStop
- 权限检查：PreHook → PermissionPolicy → 执行 → PostHook
- Hook可修改input、覆盖权限决策、添加反馈消息
- 自动压缩：当input_tokens超过阈值时自动compact_session

#### 3. runtime/permissions.rs - 权限系统 (~400行)
**PermissionMode（Ordinal，可比较）：**
- ReadOnly = 1
- WorkspaceWrite = 2
- DangerFullAccess = 3
- Prompt = 4（总是提示）
- Allow = 5（总是允许）

**PermissionPolicy 授权流程 authorize_with_context：**
1. 检查deny_rules，匹配则Deny
2. 获取current_mode和required_mode
3. 检查context.override_decision（Hook可覆盖）
4. 检查ask_rules，匹配则强制prompt
5. 检查allow_rules或mode >= required_mode，满足则Allow
6. 如果mode是Prompt，或需要升级权限，则prompt_or_deny
7. 否则Deny

**PermissionRule 规则匹配：**
- 格式：`tool_name` 或 `tool_name(matcher)`
- matcher: `*`任意, `prefix:*`前缀匹配, `exact`精确匹配
- 从input中提取subject（command/path/url等）进行匹配

#### 4. runtime/compact.rs - 会话压缩 (~400行)
**CompactionConfig：**
- preserve_recent_messages: 保留最近N条消息（默认4）
- max_estimated_tokens: 最大估计token数（默认10K）

**compact_session 流程：**
1. 检查should_compact（消息数>preserve且token>=max）
2. 提取existing_summary（如果已有压缩摘要）
3. 保留最近preserve条消息
4. 压缩中间消息：summarize_messages
5. 合并新旧摘要：merge_compact_summaries
6. 构建continuation消息（System角色）
7. 返回compacted_session

**摘要内容：**
- Scope: 压缩了多少消息
- Tools mentioned: 提到的工具
- Recent user requests: 最近用户请求
- Pending work: 待办事项（检测todo/next/pending等关键词）
- Key files referenced: 关键文件
- Current work: 当前工作
- Key timeline: 时间线

#### 5. runtime/hooks.rs - Hook系统 (~500行)
**HookEvent：** PreToolUse, PostToolUse, PostToolUseFailure

**HookRunner 执行流程：**
1. 构建hook_payload（JSON格式，包含event/tool_name/tool_input/tool_output等）
2. 通过stdin发送payload到shell命令
3. 环境变量：HOOK_EVENT, HOOK_TOOL_NAME, HOOK_TOOL_INPUT, HOOK_TOOL_OUTPUT, HOOK_TOOL_IS_ERROR
4. 解析stdout输出（支持JSON或纯文本）
5. 返回码：0=Allow, 2=Deny, 其他=Failed

**ParsedHookOutput 可包含：**
- systemMessage/reason: 反馈消息
- continue=false 或 decision=block: 拒绝
- hookSpecificOutput.permissionDecision: allow/deny/ask
- hookSpecificOutput.updatedInput: 修改后的工具输入

**HookAbortSignal：** 支持取消长时间运行的hook

#### 6. runtime/session.rs - 会话管理 (~600行)
**核心结构：**
- Session: version, session_id, created_at_ms, updated_at_ms, messages, compaction, fork
- ConversationMessage: role, blocks, usage
- ContentBlock: Text, ToolUse {id,name,input}, ToolResult {tool_use_id,tool_name,output,is_error}
- MessageRole: System, User, Assistant, Tool

**持久化格式（JSONL）：**
```
{"type":"session_meta","version":1,"session_id":"...","created_at_ms":...,"updated_at_ms":...}
{"type":"message","message":{"role":"user","blocks":[...]}}
{"type":"compaction","count":1,"removed_message_count":4,"summary":"..."}
```

**功能：**
- 原子写入（write_atomic：先写tmp再rename）
- 日志轮转（rotate_session_file_if_needed：256KB触发，保留3个历史）
- SessionFork：支持分支（新session_id，保留parent_session_id）
